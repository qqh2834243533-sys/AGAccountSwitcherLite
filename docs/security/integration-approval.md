# 真实客户端集成批准

0.1.0 无真实客户端执行入口。后续每次真实测试须事先书面列明适用的官方文档及客户端版本、测试账号类别、执行动作、可能影响的共享认证面、Agent 和工作区检查方法、停止条件及恢复方法。取得用户对该次范围的明确批准后执行。应用内四位确认仅用于防误触。

优先选择非关键账号。涉及工作区的测试优先使用空白项目。先确认活动身份与 Agent 状态可可靠观察，再分项验证。身份不明确、Agent 忙碌或状态未知、版本不明、结果验证失败或需要额外权限时停止。恢复由用户通过官方界面完成。

批准记录包含测试范围、版本、预期影响、批准时间和结果。记录排除真实账号地址、验证码、令牌、完整个人路径和会话内容。

## Antigravity App 2.34.0 轻量换号

拟在本机 Windows x64 上测试官方 Antigravity App 2.34.0 的一个桌面实例。A 和 B 均为用户可操作的非关键个人 Google 账号。试验验证 A → B → A 的身份切换，并测量两趟换号的操作量、浏览器验证要求和客户端是否重启。

Google 的文档描述了 App、CLI 和 IDE 扩展的统一认证。App 退出或重新登录可能改变同机共享认证面的有效身份，或使它们下次需要重新认证。独立 IDE 的具体行为仍待确认。用户先在现有官方界面确认没有依赖该登录的活跃工作，并接受可能需要恢复登录。试验中不启动、退出或变更其他客户端。 [Google 官方认证文档](https://antigravity.google/docs/install#unified-sign-in-across-ide-extensions)

### 开测检查和停止条件

- 开测前确认版本、实例数和活动身份 A。每次退出前，确认当前身份和 Agent 空闲，且没有运行中的后台或远程任务、待处理操作或待人工确认的动作。使用可用的官方任务面板核对。单个会话的 Overview 只覆盖该会话。无法确认受同一登录影响的工作空闲时，暂停试验。 [任务面板](https://antigravity.google/docs/side-panel/#sections) · [远程任务](https://antigravity.google/docs/remote-agents)
- 活动身份不明确、版本或实例数不符、认证异常或恢复失败时，停止试验。用户可在确认安全后通过官方 App 和浏览器恢复 A，再核实受影响的认证面。若 A 无法恢复或需要额外权限，记录原因并停止重试。 [官方退出与换号指引](https://antigravity.google/docs/workspace#option-1-use-a-personal-google-account)
- 退出、登录、账号选择和浏览器验证均由用户亲自完成。工具只记录脱敏结果和只读进程元数据。 [官方 App 登录流程](https://antigravity.google/docs/install#personal-google-account)

### A → B → A 操作和结果

1. **A 基线。** 用户在 App 内确认活动身份 A。记录主进程 PID 和启动时间，作为本轮进程对比的起点。
2. **A → B。** 用户从 App 退出，经官方登录流程选择 B。回到 App 后确认 B 已登录且界面可操作，并记录主进程和窗口变化。
3. **B → A。** 再次确认可安全退出，用同一流程切回 A。核对活动身份 A，记录主进程和窗口变化。两次均核对到预期身份，往返才算通过。

每趟从点击退出计时，到 App 回到可操作状态并确认目标身份时结束。同一时间段内记录 App 和浏览器的人工点击次数，以及浏览器是否打开和验证类型。用主进程 PID 与启动时间判断进程是否持续，另记窗口是否重建。证据不足时记为未能判定。

双账号往返成功后，以实测耗时、人工步骤和验证要求评估换号体验，再决定是否另行申请四账号试验。缺少适用的官方切换机制时保持自动切换关闭。

2026-11-23，本轮由用户亲自执行 A → B → A 的官方手动换号并回报结果。后续真实测试使用各自获批的范围。 [验收结果](../development/verification.md)
